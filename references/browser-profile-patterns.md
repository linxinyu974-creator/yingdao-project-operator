# 浏览器 Profile 模式

## 选择原则

- Excel、配置文件或用户明确提供的 Profile 映射是唯一来源；没有明确映射的账号跳过并记录原因。
- 需要已有登录态时，先激活目标 Chrome Profile，再创建或连接网页对象。
- 一个运行切片只验证一个 Profile、一个店铺和一个目标日期，成功后再扩展循环。

## 冲突处理

出现“多个用户环境/插件”时：

1. 记录目标 Profile 和当前 Chrome 实例。
2. 关闭重复的目标站点窗口或冲突实例。
3. 确认主流程没有重复启动浏览器的模块。
4. 重新激活明确 Profile，并做一次最小连接测试。

不要通过借用其他账号的 Profile、复制 Cookie 或伪造登录态来绕过冲突。需要扫码、二次验证或人工确认时，暂停在该边界并请求用户完成必要动作。

## 完成判定

Profile 激活成功只说明浏览器环境正确；还必须确认网页对象已连接、目标站点登录态有效，并且页面进入需求指定的业务入口。
