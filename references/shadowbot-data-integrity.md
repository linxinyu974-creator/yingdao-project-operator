# 数据完整性与错误传播（仅数据任务）

这是通用排查方法，不含某个业务库的固定表结构。先用当前应用调用链定位数据库及查询，读取实际 schema、索引、where/join 和写入 SQL。诊断任务只读，不重置运行标记或迁移业务行。

## 排查顺序

1. 从 app → startup → process/module → SQL 找到真实执行路径。排除同名旧模块、未发布副本和其他主体版本。
2. 记录订单/店铺/主体/日期的实际键和过滤来源；唯一键是否包含主体等维度决定“重复”是否会被数据库拦截。
3. 对 INSERT IGNORE 验证真实索引；它不等于业务去重。白名单只按店铺而没按主体时是需核查的跨主体风险，不直接认定所有库都有此问题。
4. 区分展示去重、历史归属迁移、预防新增重复三种任务，不用 DISTINCT 或保留最新代替业务归属规则。
5. stat(None) 等通常需往上查数据库/认证/查询失败是否返回 None；保留首个错误，校验路径后再做文件操作。

## 授权修改与验收

用户要求“可重跑”时，先列出精确作用域和执行标记，备份待改行并验证备份，再只重置已授权标记。不要无声改金额、主体或删除截图来模拟重跑。

脚本使用经过确认的应用解释器和 UTF-8，避免 shell 编码改变 SQL。只展示聚合证据和必要标识，不输出连接串、账号票据。

修复验收使用业务字段非空、数值/期间一致、标记一致和源账单证据，不能只看 update_time、文件存在或 HTTP 200。
