# 持续改进机制

## 目的和时机

本机制让使用本技能的代理在每次影刀任务的稳定终态主动判断：本次有没有会改变未来操作决策的、可验证的通用经验。它不是后台任务、自动记忆或自动发布机制；技能只能在被调用时执行本检查。

只在以下任一终态进行检查：任务已完成并完成结果核验；任务失败且首个阻塞已定位；任务被明确暂停且已记录恢复条件。运行中的 whole-app task、正在等待人工验证码、页面仍在下载或用户正在手工接管时，跳过检查，先保护当前执行。

## 四步复盘

1. **变化**：和本技能已有规则相比，本次是否出现新能力、失效契约、重复故障模式或更可靠的验证方法。
2. **证据**：记录可复查的来源，例如当前 CLI help/响应、任务日志、调用链、保存后的代码、稳定输出文件或官方文档；区分观察和根因推断。
3. **泛化**：说明适用条件、反例和预期受益者。只对一个 app、账号、订单、日期、页面文案或浏览器会话成立的内容属于项目记录，不是技能知识。
4. **处置**：输出 `无候选`，或生成一个候选项并决定是否等待授权、写入 reference、提升为主技能规则、补充脚本测试，或明确拒绝。

## 候选项格式

合格候选项使用下列紧凑结构；仅在存在候选项时对用户展示：

~~~text
学习候选：<一句可迁移的规则>
证据：<观察证据>；<验证证据>
范围：<适用条件与不适用条件>
建议位置：<SKILL.md | 某个 reference | 测试 | 不写入>
处置：<待授权 | 已采纳 | 拒绝，及理由>
~~~

不得复制 task ID、完整本地路径、账号、订单号、密码、Cookie、验证码答案、令牌、业务文件内容、截图原文或网站的短期 DOM/XPath 到候选项。用抽象的组件类型、稳定属性类别和验证步骤代替。

## 采纳门槛

| 目标 | 可采纳的最低证据 | 不应采纳的情况 |
| --- | --- | --- |
| 项目记录 | 本次任务的事实证据 | 仅供当前任务继续执行时，不写入本技能 |
| `references/` | 一次已验证的调用链或平台行为，且说明适用边界 | 未定位根因；页面一次性异常；仅是用户偏好 |
| `SKILL.md` 稳定规则 | 两次独立任务复现，或一条当前官方/CLI 契约，或能防止高风险误操作的确定性约束 | 需要靠业务站点、特定 app 结构或版本猜测才成立 |
| `scripts/` 或回归测试 | 可在隔离、无账号和无业务数据的夹具中证明 | 只能通过真实账号、验证码或生产任务验证 |

若新证据推翻了已有规则，更新或标注旧规则的适用版本，不叠加互相矛盾的例外。网页元素规则应优先描述稳定属性、iframe/窗口边界和验证方式；不要记录容器序号、临时 CSS 类、像素坐标或单次页面 ID。

## 写入和发布边界

用户明确授权本次维护技能时，代理可以在任务终态直接采纳合格候选项，但仍须最小化改动、更新版本记录、运行技能校验和回归测试，并同步源仓库与安装副本。没有明确维护授权时，代理只报告候选项，不写 skill 文件、不提交 Git、不推送远端。

任何候选项都不得改变本技能的授权边界：它不能要求后续代理擅自登录、处理验证码、运行收费任务、删除数据、发布应用或推送 Git。候选项不能覆盖当前用户请求或当前环境的事实。
