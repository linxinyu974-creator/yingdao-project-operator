# 店铺切换与直接跳转

先声明切换模式，再修改流程。四种模式不可互相替代：

| 模式 | 实际动作 | 必要输入 | 完成证据 |
| --- | --- | --- | --- |
| `profile` | 激活对应 Chrome/Profile 或重新连接浏览器 | Profile 标识、账号映射 | 浏览器实例与登录态属于目标账号 |
| `in-page` | 在当前页面打开店铺选择器并点击店铺 | 店铺名或 ID、稳定 selector | 页面显示目标店铺，当前 ID 与输入一致 |
| `api` | 调用已确认的切店接口或平台动作 | 已验证接口、请求参数 | 响应成功且页面上下文更新 |
| `direct-url` | 导航到已确认包含店铺上下文的 URL | URL 模板、店铺 ID | 导航前后 URL、页面标题、页面店铺 ID/name 均正确 |

## 判定规则

- 只有已从当前应用、页面网络请求或官方资料验证过的 URL/API 才能使用 `direct-url`/`api`；禁止猜测路由参数。
- `browser.navigate` 到固定业务页只证明页面导航，不证明店铺切换；`mode="reload"` 且 `url=""` 只是刷新。
- 读取当前店铺 ID 是校验动作，不是切换动作。
- 流程名包含“新”“优化”或“跳转至新网址”不构成证据；继续追踪其下游是否仍点击旧店铺列表。
- 复用已有登录态时，不复制 Cookie、不借用其他账号 Profile；遇到扫码、二次验证或人工确认就在该边界暂停。

## 常见反例

调用 `browser.navigate` 打开店铺列表，再等待旧/新店铺元素并执行 `get_all_elements`、遍历和 `click`，实际仍是 `in-page` 模式。即使流程块名称带有“新”或“跳转”，也不能标记为 `direct-url`。同样，读取页面 HTML 中的当前店铺 ID并执行 reload 只属于校验/刷新。

## 最小验证

单 Profile、单店铺、单日期验证一次：记录目标 `shop_id/name`、切换前后 URL、页面标题、页面显示的 `shop_id/name`、实际调用节点和失败回退。若任一字段无法读取，状态只能记为“未验证”，不能报告为直接跳转成功。
