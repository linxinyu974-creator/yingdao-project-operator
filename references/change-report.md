# 修改证据报告

完成任务后按以下结构汇报，避免把推断写成事实：

```markdown
## 目标
- 用户要改变的实际行为：
- 目标 app/flow：

## 定位
- 调用链：
- 负责动作的文件、行号或 block ID：
- 修改前行为证据：

## 修改
- 修改文件和最小变更：
- 是否保存应用：是/否
- 静态诊断：通过/失败/未执行

## 验证
- 最小运行输入（Profile、店铺、日期）：
- 页面证据（URL、标题、关键字段）：
- 数据/文件证据（路径、表头、行数或关键字段）：

## 边界
- 已知失败/跳过项：
- 未验证项与需要人工介入的步骤：
```

“页面打开”“文件存在”“诊断通过”只能作为单项证据；只有与需求字段一致并完成上下文校验，才能报告整体成功。
