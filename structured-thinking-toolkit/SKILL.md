# Structured Thinking Toolkit

Choose the smallest reasoning method that materially improves the result. Keep the user's objective and requested deliverable in control; the method supports the task rather than replacing it.

## Route

Classify the current bottleneck, then read only the matching reference:

- The real question is unclear or the user's account mixes facts, interpretations, values, and goals: read [clarify.md](references/clarify.md).
- The user wants to understand, learn from, reverse-engineer, or deeply research something: read [learn-and-research.md](references/learn-and-research.md).
- A claim needs checking or a difficult problem needs new solution paths: read [solve-and-verify.md](references/solve-and-verify.md).
- The user is choosing between defensible options or needs evidence before committing: read [decide-and-experiment.md](references/decide-and-experiment.md).
- The user explicitly wants structured reflection about strengths, direction, career, or life design: read [self-reflection.md](references/self-reflection.md).

If several branches apply, begin with the earliest blocker. Chain a second method only after the first method produces an explicit handoff, such as a clarified question, verified premise, real disagreement, or testable hypothesis.

## Shared Contract

1. State the selected method in one short sentence only when that context helps the user follow the interaction.
2. Separate observable facts, interpretations, value judgments, assumptions, and goals whenever they are being conflated.
3. Ask one question at a time in interactive methods. Each question must be capable of changing the conclusion; stop as soon as the decision-relevant information is sufficient.
4. Match evidence claims to available tools. Label unsupported points as hypotheses, and never imply that simulated roles are real experts.
5. End with a concrete output suited to the request. For action-oriented work, include the next reversible step, its success signal, and a stopping or reconsideration condition.

## Completion

The reasoning pass is complete when the bottleneck has become one of these checkable artifacts: a precise question, an explanation the user can test, transferable rules, an evidence ledger, a solution with conditions and risks, a decision with its decisive variable, or a bounded experiment. Continue with the user's underlying task after producing that artifact unless the user asked only for analysis.
